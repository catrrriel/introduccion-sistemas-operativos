## Introducción 

### Sistema operativo

Es la parte esencial de cualquier sistema de cómputo. Es un programa que actúa como intermediario entre el usuario y el hardware.

Tiene como propósito generar un entorno cómodo y eficiente para la ejecución de programas; y como obligación garantizar el correcto funcionamiento del sistema.

Funciones principales:
- Administrar la memoria.
- Administrar la CPU.
- Administrar los dispositivos E/S.


### Unix

Es un SO multi-usuario, multitarea y de alta portabilidad creado originalmente en 1969 por investigadores de los laboratorios Bell de AT&T. Nació con una filosofía de diseño enfocada en mantener un sistema pequeño y simple, corrigiendo las complejidades de su predecesor, Multics.

El termino Unix se diferencia según el ambiente donde es usado:

- La familia UNIX (criterio técnico): Sistemas operativos que comparten criterios de diseño e interoperabilidad comunes, sin que esto signifique que compartan código o propiedad intelectual.

- UNIX original (criterio histórico): Sistemas que descienden directamente del código de AT&T y comparten su propiedad intelectual (como System V o BSD)

- La marca UNIX (criterio legal/comercial): Una marca de mercado propiedad de The Open Group. Cualquier sistema operativo que pase las pruebas de compatibilidad (Single Unix Specification) puede usar la marca, sea o no descendiente del código original. 

> Propiedad intelectual refiere a compartir código fuente registrado, patentes o derechos de autor de la implementación original.

### ¿Qué es una ISO?

Una imagen ISO (o archivo .iso) es un único archivo que representa una copia o clon exacto del contenido y la estructura de un soporte óptico, como un CD o DVD.

> El nombre proviene del estándar de sistema de archivos ISO 9660, que es la norma internacional que define cómo se estructuran y organizan jerárquicamente los datos en soportes de almacenamiento óptico para garantizar la compatibilidad entre distintos sistemas operativos de manera unificada

Una ISO Booteable (o de arranque) es una imagen de disco que, además de contener los archivos de instalación o el SO en sí, incluye un sector de arranque estructurado con un código de inicio (bootloader).

Cuando se graba esta ISO en un medio físico (pendrive o CD) o se monta directamente en la lectora virtual de un entorno como VirtualBox:

1. Al encender la máquina, el firmware del HW (sea la clásica BIOS o el estándar moderno UEFI) ejecuta el proceso de inicio o bootstrap

2. El firmware lee e inicializa la computadora buscando sectores de arranque específicos (como el Master Boot Record - MBR o una partición de sistema en sistemas GPT/UEFI) en los dispositivos conectados en un orden de prioridad determinado.

3. Si detecta la firma de booteo en el medio donde esta la ISO, carga en la memoria RAM el código del gestor de arranque (bootloader) que viene dentro de la imagen.

4. Este gestor de arranque toma el control y se encarga de cargar la imagen del Kernel del SO para comenzar la instalación o ejecutar un sistema en vivo (Live CD) sin tocar el disco rígido.

## 1. Características de GNU/Linux 

### A. Mencione y explique las características más relevantes de GNU/Linux.

- Está diseñado por miles desarrolladores, es gratuito y de libre distribución (se baja desde la Web, ISO booteable).

- Es un SO de tipo Unix (Unix like), pero libre. 
  
> Que un sistema sea "Unix-like" significa que fue diseñado para ser compatible con la arquitectura, la filosofía y el comportamiento de UNIX, pero sin utilizar su código fuente original ni propiedad intelectual protegida.

- Multi-usuario

> A diferencia de un núcleo monolítico clásico estático, el kernel de Linux puede cargar y descargar módulos de software (como drivers de dispositivos) de manera dinámica en tiempo de ejecución sin necesidad de reiniciar el sistema operativo

- Portabilidad

> Fue diseñado para abstraer el HW, hoy en día corre en casi cualquier arquitectura de procesador. (x86, ARM, PowerPC, etc.)

### C. ¿Qué es GNU?

GNU es un proyecto iniciado por Richard Stallman en 1983 con el objetivo de desarrollar un SO libre que fuera compatible con UNIX.

### D. Indique una breve historia sobre la evolución del proyecto GNU.

Evolución e importancia histórica:

- La licencia **GPL** (copyleft): Para asegurar que GNU siga siendo libre, la Free Software Foundation (FSF) creó la **Licencia Pública General** (GPL), que protege las cuatro libertades del SW libre:
  - Usar con cualquier propósito 
  - Estudiar su funcionamiento
  - Distribuir sus copias
  - Mejorar el código

- El sistema GNU: Para 1990, el proyecto ya había completado casi todas las piezas de un sistema tipo Unix: el compilador (GCC), editores de texto (Emacs), intérpretes de comandos (Shell) y la mayoría de bibliotecas y utilidades.

- El núcleo faltante: Al proyecto le faltaba el Kernel. Su propio intento de núcleo, GNU Hurd, se estanco por problemas técnicos.

- La fusión GNU/Linux: En 1992, el núcleo Linux desarrollado por Linus Torvalds (que se distribuía bajo la misma licencia GPL) se combinó con el sistema de utilidades de GNU para dar a luz al SO completamente funcional que hoy llamamos GNU/Linux.

### E. Explique qué es la multitarea, e indique si GNU/Linux hace uso de ella.

Es la capacidad de un SO para ejecutar múltiples procesos de manera concurrente.

En un procesador de un solo núcleo, la ejecución de los programas se intercala en el tiempo → el SO divide el tiempo de uso del procesador en fracciones minúsculas (time slices) y va rotando la CPU de un proceso a otro extremadamente rápido.

GNU/Linux implementa un esquema de multitarea expulsiva (o apropiativa) → el planificador del kernel tiene el control total sobre el tiempo de la CPU. Si un proceso agota su "rodaja" de tiempo, o si ingresa un proceso de mayor prioridad, el kernel suspende la ejecución del proceso actual y entrega el procesador al nuevo proceso. 

### F. ¿Qué es POSIX?

**Portable Operating System Interface** es una familia de estándares formales definidos por la IEEE (Institute of Electrical and Electronics Engineers) con el objetivo de garantizar la portabilidad y la compatibilidad de SW entre distintos sistemas operativos de la familia Unix.

Define de manera unificada como deben comportarse las interfaces de programación de aplicaciones (las API de las System Calls en C), el intérprete de comandos (Shell), las utilidades básicas y la gestión de procesos e hilos.

## 2. Distribuciones de GNU/Linux

### A. ¿Qué es una distribución de GNU/Linux? Nombre al menos 4 distribuciones de GNU/Linux y cite diferencias básicas entre ellas.

Una "distro" de Linux es un conjunto de aplicaciones que buscan facilitar la instalación y configuración de un SO basado en GNU/Linux dependiendo del propósito que se le vaya a dar a la herramienta (al sistema).

La composición base de cada distribución incluye siempre el núcleo Linux, con las bibliotecas y herramientas del proyecto GNU y de muchos otros proyectos/grupos de software, como BSD por ejemplo.

Existen muchas y cada una tiene sus características propias. Algunas son armadas sobre la base de otra distro anterior, lo que da pie a categorizar a algunas como "distribuciones principales":

- Debian: Caracterizada por su filosofía de SW estrictamente libre. Su prioridad absoluta es la estabilidad del sistema. Utiliza el formato de paquetes `.deb` y el gestor de paquetes `apt` (Advanced Package Tool)

- Arch Linux: Con una filosofía de simplicidad e instalación "Do It Yourself", orientada a usuarios avanzados. No posee instalador gráfico por defecto y utiliza un modelo de actualización continua (Rolling Release) donde el sistema se actualiza constantemente sin requerir reinstalaciones de versión. Gestor de paquetes nativo `pacman`.

- Gentoo: Orientada a la personalización extrema y al alto rendimiento. La diferencia con las demás distros es que descargan programas ya compilados (binarios), acá casi todo el SW se descarga en código fuente y se compila localmente en la máquina optimizándolo para el procesador específico. Gestor de paquetes `Portage`.

- RedHat Enterprise Linux: Distribución comercial enfocada directamente en servidores, supercomputadores y entornos corporativos. Ofrece soporte técnico de pago y un entorno predecible y seguro. Utiliza el formato de paquetes `.rpm` y el gestor de paquetes `dnf` (anteriormente `yum`)  

De estas descienden algunas con gran relevancia como:

- Ubuntu → basada en Debian
- Fedora → continuación del proyecto RedHat
- Red Hat Enterprise → basada en RedHat

### B. ¿En qué se diferencia una distribución de otra?

Se diferencian entre sí en sus herramientas de configuración y sistemas de administración de paquetes de software para instalar.

En general y a nivel de arquitectura, principalmente en:

- Sistemas de administración de paquetes: cada familia de distros tiene su propio formato de empaquetado (ejemplo `.deb` para Debian/Ubuntu o `.rpm` para RedHat/Fedora) y sus herramientas de resolución de dependencias (como `atp`, `dnf` o `pacman`).

- Herramientas de configuración y administración: Varian en sus utilidades de sistema, scripts de inicialización del sistema
(como SystemV o SystemD) y facilidades de configuración por consola o interfaz gráfica.

- Interfaz gráfica: La mayoría soporta cualquier entorno o interfaz, pero todas eligen una por defecto (como GNOME, KDE, XFCE o LXDE) para sostener una identidad visual.  

- Filosofía y ciclo de vida de las versiones: Mientras algunas priorizan la estabilidad para servidores (Debian, RHEL) otras se enfocan en tener siempre el SW de vanguardia (Arch, Fedora)


### C. ¿Qué es Debian? Acceda al sitio https://www.debian.org/ e indique cuáles son los objetivos del proyecto y una breve cronología del mismo.

Debian es una asociación de individuos comprometidos con la creación de un SO totalmente libre. Se destaca en el ecosistema IT por su robustez técnica, su estabilidad, su rigurosa política de calidad y un modelo de desarrollo comunitario independiente de cualquier control comercial o corporativo.

Objetivos según su Contrato Social:

- Crear un SO 100% libre: Todo el SW que forme parte de la distribución oficial debe cumplir estrictamente con las Directrices de software libre de Debian (DFSG).

- Priorizar a los usuarios y al SW libre: El proyecto formaliza su compromiso de dar soporte preferencial a sus usuarios y de mantener el sistema libre de regalías o restricciones mediante su Contrato Social.

- Ofrecer estabilidad y seguridad técnica: Su desarrollo está enfocado en proveer un entorno seguro, predecible y de alta compatibilidad para servidores y estaciones de trabajo basados en la arquitectura tipo Unix.

- Devolver las mejoras a la comunidad de SW: Todo error solucionado o mejora desarrollada dentro del proyecto se comparte de manera pública para beneficiar a todo el ecosistema de SW libre. 

Cronología:

- 16 de agosto de 1993: Ian Murdock anuncia formalmente el proyecto Debian (el nombre surge de la combinación de su nombre y el de su novia, Debra).

- Enero de 1994: Se lanza la versión Debian 0.91, la última versión compilada de forma totalmente artesanal por Murdock, que introdujo un sistema de empaquetado primitivo que sentó las bases para el futuro del proyecto.

- Noviembre de 1994 – Noviembre de 1995: El proyecto recibe el patrocinio financiero y logístico de la Free Software Foundation (FSF) de Richard Stallman, lo que acelera de forma drástica su crecimiento.

- Marzo de 1995: Se publica Debian 0.93 Release 5, considerada la primera versión "moderna" de la distro. Se consolida el uso de la herramienta `dpkg` para el manejo de paquetes individuales y los desarrolladores comienzan a administrar sus propios paquetes de manera descentralizada.

- Noviembre de 1995: Se lanza Debian 0.93 Release 6, la última versión que usó el formato binario antiguo `a.out` y en la cual aparece por primera vez la herramienta interactiva de selección de paquetes `dselect`.

- Junio de 1996: Se publica Debian 1.1 (Buzz), la primera versión estable oficial en formato binario moderno ELF. (Nota: se salteó la numeración 1.0 porque una distribuidora de CD-ROMs vendió por error una versión preliminar de desarrollo etiquetándola como versión 1.0 estable).

- Diciembre de 1998: Se ratifica la primera Constitución del Proyecto Debian, estructurando de forma democrática los roles internos, la elección del líder del proyecto (DPL) y el mecanismo de toma de decisiones.

- Actualidad: Sigue siendo una de las distribuciones no comerciales más activas y de mayor influencia en la industria, funcionando como el cimiento técnico directo sobre el cual se construyen sistemas operativos masivos como Ubuntu, Kali Linux o Linux Mint.

## 3. Estructura de GNU/Linux

### A. Nombre cuáles son los componentes fundamentales de GNU/Linux.

Hay tres elementos fundamentales en GNU/Linux:

1. Kernel (núcleo): Corazón del sistema, encargado de que el SW y el HW trabajen coordinados.

2. Shell (intérprete de comandos): Programa que actúa como interfaz entre el usuario y el SO. Traduce los comandos a instrucciones comprensibles para el sistema.

3. FileSystem (sistema de archivos): Esquema organizativo que determina como se estructuran, acceden y protegen los archivos y directorios dentro del almacenamiento físico.
   
Se puede sumar como elemento fundamental a las siguientes herramientas y utilidades que permiten personalizar el entorno:

- Editores de texto → vi, nano
- Compiladores → CCG 
- Interfaz gráfica → GNOME, XFCE, etc... 

### B. Mencione y explique la estructura básica del Sistema Operativo GNU/Linux.

1. Filosofía de diseño en capas y portabilidad → Fue desarrollado buscando la portabilidad de los fuentes y adoptando un desarrollo en capas con estricta separación de funciones
   
   - Cada capa funciona como una "caja negra" respecto a las otras. Una capa superior (como el Shell) no necesita conocer los detalles de implementación interna de la capa inferior (Kernel), sino únicamente saber cómo comunicarse con su interfaz de llamadas al sistema (System Calls).

   - El diseño modular facilita el desarrollo distribuido (muchos programadores codeando en simultaneo) y permite dar soporte nativo a diversos File Systems.

2. Kernel Monolítico Modular (o Híbrido) → SO básico que se ejecuta en modo privilegiado (modo kernel) con control absoluto de la CPU, memoria y el HW. Reside en RAM.

   - A diferencia de un núcleo monolítico clásico cerrado, en Linux, aunque todo el núcleo corra en un mismo espacio privilegiado de memoria, se tiene la capacidad de cargar y descargar dinámicamente funcionalidades (módulos cargables como drivers o sistemas de archivos) en caliente, sin tener que compilar todo de cero o reiniciar la máquina física.

3. Shell → Programa común que se ejecuta en modo usuario (no privilegiado) que actúa como traductor de las ordenes del usuario.
   - La Shell no forma parte del kernel básico del SO, sino que dialoga con él mediante System Calls. Esto provee protección, ya que si la terminal falla o se cuelga, el kernel sigue intacto y la máquina sigue funcionando.

   - Al ser un programa independiente, cada usuario puede tener una Shell configurada a su comodidad. Los mas populares son `bash`, `sh`, `zsh` o `ksh`

4. FileSystem → Estructura jerárquica unificada (cuyo estándar adoptado por Debian es la familia **extended: ext2, ext3, ext4**) que organiza el almacenamiento secundario bajo dos premisas:
   
   - Everything is a file: El SO mapea y trata de la misma forma lógica a un archivo de texto común, a un directorio (archivo especial que asocia nombres con índices), o a un dispositivo físico de HW (como el disco SATA `/dev/sda` o una terminal de consola en `/dev/tty`).

   - Estructura en Árbol: Información organizada de forma jerárquica partiendo de un único directorio raíz denominado `/`. Siguiendo el estándar FHS.

## 4. Kernel

### a. ¿Cuáles son sus funciones principales?

El Kernel (o **núcleo**) es, en un sentido estricto, el SO en sí mismo. Componente fundamental y el "corazón del sistema" encargado de que el hardware y el software puedan trabajar juntos.

El Kernel se encuentra siempre residente en la memoria principal (RAM). Desde ahí administra de manera directa todos los recursos físicos:

- **Gestión del CPU**: Se encarga de la creación, planificación, sincronización e intercambio de los procesos que compiten por tiempo de procesador.

- **Gestión de la memoria**: Reserva el espacio de direcciones para los procesos y maneja esquemas complejos como la memoria virtual y el swapping.

- **Gestión de Entrada/Salida (E/S)**: Administra los dispositivos físicos (discos, placas de red, terminales) mediante controladores de dispositivos (**drivers**).

Para evitar que un programa con errores rompa todo el sistema, el HW del procesador implementa distintos niveles de privilegio:

- Modo Usuario: Modo no privilegiado donde corren las aplicaciones de usuario y las utilidades comunes. Los procesos acá trabajan aislados en su propio espacio de direcciones y no pueden interactuar directamente con el HW.

- Modo Kernel (o Supervisor): Modo privilegiado donde se ejecuta el núcleo. Acá el SW tiene un control completo e irrestricto del procesador, las instrucciones y la memoria. 
  
  Si un programa en modo usuario intenta hacer algo ilegal como tocar el HW de manera directa, el el procesador genera un *trap* (excepción) que le devuelve el control al kernel para tomar las medidas necesarias de inmediato.

¿Cómo interactúan los programas con el kernel?

Como los procesos en modo usuario no pueden acceder directamente al HW, cuando necesitan realizar alguna acción privilegiada (como leer un archivo o enviar datos por red) deben solicitarle permiso al kernel mediante una **System Call**.

Al ejecutarse la llamada se produce el cambio a modo supervisor de manera segura, para que el núcleo realice la tarea en su nombre, y luego se restablece el modo usuario para seguir con la ejecución de la aplicación.

### B. ¿Es posible tener más de un Kernel de GNU/Linux instalado en la misma máquina?

Sí, es posible y es una práctica estándar en los sistemas tipo Unix.

Cuando se realiza una actualización del SO y se descarga una versión mas nueva del núcleo, el gestor de paquetes no elimina de inmediato al kernel anterior para evitar dejar la máquina inoperable en caso de que la nueva versión presente alguna incompatibilidad con el HW.

Ambos kernels residen físicamente en el disco. Al encender la computadora, el GRUB (gestor de arranque, cuya configuración se lee desde `/boot/grub/grub.cfg`) detecta todos los kernels disponibles y presenta un menú interactivo en pantalla.

En el ejemplo, si la versión mas reciente falla, se puede reiniciar, ir a las "opciones avanzadas" del menú y seleccionar iniciar con la versión anterior.

### C. ¿En qué directorio se encuentra ubicado?

Los archivos binarios ejecutables del núcleo y sus herramientas de arranque están en el directorio `/boot`

En este directorio, por cada versión de kernel instalada hay principalmente tres archivos:

- `vmlinuz-<versión>`: Es el ejecutable comprimido del kernel de Linux que se carga en la RAM para inicializar el sistema.
  
- `initrd.img-<versión>`: Es la imagen del disco RAM inicial (initial ramdisk) que contiene los controladores temporales necesarios para que el kernel pueda montar el sistema de archivos raíz (/) antes de arrancar.

- `config-<versión>`: El archivo que detalla los parámetros con los que fue compilado ese núcleo específico.
  
> Nota: El código fuente del núcleo (las líneas de código antes de ser compiladas) se encuentran en `/usr/src/linux`.

## 5. Intérprete de comandos (Shell)

### A. ¿Qué es y cuáles son sus funciones?

Programa que actúa como intermediario entre el usuario y el kernel. 
Funciones principales:

- Traducción y ejecución de comandos: Analiza la linea de comandos ingresada, identifica si se trata de una orden interna o externa, y solicita su ejecución al kernel.

- Gestión de variables de entorno: Administra variables dinámicas de configuración del entorno de trabajo, como `PATH` (que define dónde buscar los archivos ejecutables) y `PWD` (que registra la ruta del directorio de trabajo actual).

- Programabilidad (Shell Scripting): Permite agrupar secuencias de instrucciones en archivos de texto (scripts) para automatizar la ejecución de tareas complejas de forma secuencial.

- Redirección y control de E/S: Permite alterar los flujos estándar de datos (teclado como _stdin_, pantalla como _stdout_ y _stderr_) mediante operadores de redirección (`<`, `>`, `>>`) o el encadenamiento de procesos a través de tuberías (`|`).

- Control de trabajos y procesos: Facilita la administración de los programas en ejecución, permitiendo lanzar comandos tanto en primer plano (_foreground_) como en segundo plano (_background_ utilizando el carácter `&`).

### C. ¿Dónde se ubican (path) los comandos propios y externos al Shell?

**Comandos internos (propios)**: Están incorporados dentro del propio shell, no tienen un ejecutable en el disco ni una ruta física de almacenamiento, residen dentro del binario del intérprete de comandos. Ejemplo: `cd`, `echo`, `exit`, `pwd`

**Comandos externos**: Son programas independientes que viven en el FS. Se ubican principalmente en `/bin`, `/usr/bin`, `/sbin`, `/usr/sbin`. Se puede ver la ubicación de cualquier comando usando `which <comando>`.

> Se puede usar `type <comando>` en Debian para que Shell muestre si es interno o externo

### D. ¿Por qué considera que el Shell no es parte del Kernel de GNU/Linux?

1. **Seguridad y estabilidad (aislamiento)**: Shell se ejecuta como un proceso común en modo usuario. Si este formara parte del Kernel (que ejecuta en modo supervisor), cualquier falla o vulnerabilidad al procesar comandos podría corromper el núcleo o colgar todo el SO.

2. **Flexibilidad y personalización**: Al ser un programa externo que se comunica con el Kernel únicamente a través de System Calls, permite que el entorno sea altamente flexible. Diferentes usuarios en la misma máquina pueden ejecutar e interactuar con diferentes consolas de manera simultánea sin necesidad de alterar o reiniciar el Kernel .

### E. ¿Es posible definir uno distinto para cada usuario?

Sí. 
En los sistemas tipo Unix, cada cuenta de usuario tiene asignado un Shell predeterminado. Esta asignación está registrada en `/etc/passwd`.

Cuando un usuario inicia sesión en una terminal, el proceso `login` valida sus credenciales, lee su línea correspondiente en `/etc/passwd`, identifica cuál es la ruta del intérprete de comandos asociada en el último campo (por ejemplo, `/bin/bash` o `/bin/sh`) y lo inicializa automáticamente de manera exclusiva para esa sesión de trabajo.

## 6. El sistema de Archivos (File System) en Linux:

### A. ¿Qué es?

Es la estructura lógica que usa el SO para organizar, almacenar y acceder a los datos en un dispositivo de almacenamiento (disco, pendrive, etc.). Define cómo se nombran y guardan los archivos, cómo se organizan los directorios y cómo se gestionan los metadatos.

### B. ¿Cuál es la estructura básica de los File System en GNU/Linux? Mencione los directorios más importantes e indique qué tipo de información se encuentra en ellos. ¿A qué hace referencia la sigla FHS?

FHS (Filesystem Hierarchy Standard): Norma de estandarización que define la estructura de directorios y que contenido debe ir en cada uno dentro de los sistemas Unix-like.

Los mas importantes:

  - `/` → Raíz del sistema. Idem `C:\`
  - `/home` → Archivos de usuarios (mis documentos)
  - `/root` → Directorio personal del usuario root. 
  - `/var` → Información que varia de tamaño (logs, BD, colas) 
  - `/etc` → Archivos de configuración del sistema.
  - `/bin` → Archivos binarios y ejecutables
  - `/sbin` → Comandos para la administración del sistema (para root).
  - `/dev` → Enlace a dispositivos
  - `/tmp` → Archivos temporales (se borran al reiniciar).
  - `/usr` → Aplicaciones de usuarios 
  - `/lib` → Bibliotecas compartidas esenciales. 
  - `/proc` → Sistema de archivos virtual con información de procesos. 
  - `/boot` → Archivos necesarios para el arranque (Kernel, GRUB).

Cada File System implementa diferentes algoritmos y estructuras para resolver cómo mapear el concepto lógico de los archivos creados por los usuarios y procesos en los dispositivos de almacenamiento (discos).
